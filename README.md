## 📌 О проекте

В отличие от прямого обращения к HTTP-сервисам 1С, JSON-RPC шлюз обеспечивает единую точку входа между Python-приложением и сервером 1С Предприятие через сокетное соединение. Модуль реализует низкоуровневый транспорт, маршрутизацию вызовов API, валидацию схемы запросов и неизменяемый аудит транзакций. Архитектура ориентирована на низкую задержку, двусторонний обмен сообщениями и предсказуемую обработку отказов транспортного уровня.

## ⚙️ Функциональные возможности (Behavior-Driven Development)

Архитектура модуля спроектирована с использованием методологии **BDD (Behavior-Driven Development)**. Все функции описаны на языке Gherkin (русская локализация), что обеспечивает прозрачность логики для разработчиков, тестировщиков и заказчика.

### Ключевые сценарии работы:

- **Health Check (Сценарий):** Базовый сценарий проверки доступности шлюза — клиент отправляет JSON-RPC запрос с методом `ping` и ожидает ответ `pong`. Применяется для мониторинга и диагностики потери связи с 1С.

- **Валидация методов API (Outline):** Тестирование реакции шлюза на различные вызовы методов с использованием блока «Примеры»:
   - **`get_data` →** статус `200 OK` (успешное чтение данных).
   - **`delete_all` →** статус `403 Forbidden` (запрет деструктивной операции).
   - **`unknown` →** статус `404 Not Found` (неизвестный метод).

- **Транспортный уровень (Background):** Общее предусловие для всей группы тестов — установленное Socket-соединение между Python и 1С. Гарантирует, что зависящие от транспорта сценарии не запускаются при разорванном канале.

- **Передача сложного JSON (DocString):** Отправка многострочного JSON-пакета с вложенными массивами и объектами через метод `bulk_upload`. Позволяет загружать в 1С большие наборы данных одной транзакцией.

- **Структура ответа (DataTable):** Верификация схемы JSON-RPC ответа таблицей полей и их типов (`result: object`, `error: null`, `id: integer`). Гарантирует совместимость десериализации на стороне клиента.

- **Обработка таймаута:** Прерывание соединения и возврат ошибки `Timeout` при превышении времени ожидания ответа от 1С (5 секунд). Сценарий написан с использованием русских ключевых слов Gherkin (`Если`, `Тогда`).

## 🎨 Проектирование интерфейса (UI/UX)

Визуальная часть модуля разработана с соблюдением принципов **Enterprise UI Design**, ориентированных на работу с большими объёмами транзакций и плотными таблицами данных. Все макеты созданы в **Pixso** с использованием системных компонентов и Auto Layout.

### Основные компоненты интерфейса:

1. **Главная панель мониторинга (Main Panel):** Дашборд состояния шлюза с виджетами активных Socket-соединений, счётчиками транзакций в реальном времени и индикаторами здоровья сервиса. Цветовое кодирование статусов (зелёный — норма, жёлтый — деградация, красный — отказ).

   ![Главная панель](docs/ui_prototypes/screen_layout_1.png)

2. **Настройки интеграции (Integration Settings):** Экран конфигурации параметров Socket-канала, JWT-ключей подписи, таймаутов и лимитов нагрузки. Раздельные блоки для боевого и тестового контуров с валидацией значений на стороне клиента.

   ![Настройки интеграции](docs/ui_prototypes/screen_layout_2.png)

3. **Журнал транзакций (Transactions Log):** Табличное представление всех вызовов API с фильтрацией по методу, статусу и временному диапазону. Поддержка пагинации, сортировки и быстрого перехода к деталям отдельной транзакции.

   ![Журнал транзакций](docs/ui_prototypes/screen_layout_3.png)

## 🛠️ Технологический стек

| Технология              | Назначение                                                |
|-------------------------|-----------------------------------------------------------|
| **Python 3.11+**        | Реализация интеграционного слоя и клиента шлюза.          |
| **JSON-RPC 2.0**        | Протокол прикладного уровня для вызова процедур 1С.       |
| **TCP Socket**          | Низкоуровневый транспорт двустороннего обмена сообщениями.|
| **Gherkin / Cucumber**  | Написание и выполнение BDD-сценариев тестирования.        |
| **OpenAPI (YAML)**      | Формальное описание методов API и схем сообщений.         |
| **Pixso**               | Прототипирование интерфейсов и экспорт макетов.           |
